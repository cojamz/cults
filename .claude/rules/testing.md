# Before any bot games, sims or judging (Cory, Nov 12)

Cory, Nov 12, after an hour of today's bots playing each other while the skill ideas sat unbuilt: "whats the point in spending my fucking tokens on what we already knew???", "just testing our existing bots and ignoring all the principles we cam up with", "self improve in lasting and sustainable ways. Now."

1. **Write the question in Cory's words and the answer we expect.** If we already know the answer (a stronger bot beats a weaker one, a nerf makes a card worse), don't run it. Baselines and "how much room is there" checks are not results; never run them first or send them as findings.
2. **One change against a named control.** The run plays the thing Cory asked about (his idea, his card, his principle, built) against the game or bot as it is today, on the same deals.
3. **Skill tests**: one principle from design/notes/skilled-play-2026-11-12.md built into the strongest bot, against the strongest bot as it is today. Never one existing level against another.
4. **No Fable tokens on runs.** Fable is for ideas and for building the bots. Bot games, sims, judging and reporting them run on a cheaper model (ask Cory once to switch the thread, or hand the run to a runner thread). The games themselves are plain code and cost no tokens; the turns around them do.
5. **Every game has a time limit** (`--limit=<seconds>` on scripts/v4-bot-duel.mjs and scripts/skill/*.mjs), so one stuck game can't hold a run.
6. **Check a long run every 30 minutes** (schedule the check when you start it), and post before a promised time passes, with what is done and the new time.
