# How we work: overnight once-over (Nov 1, 2026)

Short version: the browser tests went red because nothing ran them regularly and nothing showed the result to the next thread. That's fixed. The thread board had a bug that made every thread overwrite every other thread's line, which is part of why threads looked stale. Also fixed. Below: what I found, what I fixed tonight, and what I'd change next with your OK.

## What I fixed tonight (all live for every new thread)

**1. A full browser check every 4 hours, on GitHub's machine.**
Ships only ran the quick unit tests, and a full check with the browser games takes 6 to 20 minutes on our busy 4-core box, so threads mostly skipped it. Over four days we shipped about 140 releases and almost never ran it. Each box's check record was also wiped when its container closed, so nobody could see the last result. Now GitHub runs the whole gate on the newest game code every 4 hours. The first run is about 4:23am. The result goes to a small results branch, and it prints at the start of every thread and on every ship, like: "Browser verdict on 4d9a2d8 (2h ago, 5 commits behind): RED (2): pay.mjs, tables.mjs". The job never shows as failed, so you get no emails from it.

**2. The thread board shows every thread again.**
Every chat thread was saving its status under the same name, so each update wiped out the one before it. That's why the board only ever showed one thread and others looked quiet. Each thread now gets its own line.

**3. The balance tools.**
Very Hard bots in balance games ran on a 600 ms thinking clock. That made results depend on how busy the box was, and the same game number didn't play the same game twice. Very Hard now runs uncapped, the way Hard already did. The older Hard batch script never asked which deck (10 or 15) and silently used 15. It now refuses to start until a deck is named, like the other scripts.

**4. Fewer stuck ships when threads collide.**
The decision log, pitch ledger and lessons files now keep both sides automatically when two threads add lines at the same moment. Those clashes had stopped ships at least twice. The quick ship script also retries when another thread pushes first, instead of failing.

**5. Small fixes.** The known-red list printed "undefined" for its own entries. Every box's check runs now also go to a shared record in the project folder.

## What I found that still needs a change

**Gates go stale when cards change.**
Most of the 16 reds were tests still checking an old card's text or an old look after a change Cory had approved. We have a rule that a change to a gated look updates its test in the same commit, but quick ships never run those tests, so nobody saw them break. The 4-hourly check now catches a break within hours. The next step would be for a ship that changes a card to also run the browser tests that mention that card (a one or two minute addition). I'd build it next.

**Big releases should wait for a green check.**
v0.99 and 1.0 should only go out on a commit the full check passed. I've told the coordinator. Small ships keep the fast lane.

**The hand-off docs lag.**
HANDOFF.md was last rewritten Oct 28 and in-flight.md on Oct 29, with live versions 0.9.801 and 0.9.854. Live is 0.9.937. Every thread is warned at start, and nobody updates them, so a fresh thread can't trust either one. I'd generate the "what's live and what's running" part automatically from the version stamp, the board and the changelog, and keep the hand-written part to open questions and owners.

**Card text has three homes.**
Card text lives in the game's card files. The decision log quotes it at the moment of each call, and reports and pitches quote whatever they read. The rulebook barely names cards, so it isn't the problem (I checked every bold name in it). The risk is a pitch or report quoting old text: last night's balance report quoted the old **Greatest Hits** ("Copy every action with your minion") after the new text had been decided. I'd add a generated list of every card's live text, refreshed on every ship, for threads and ChatGPT to quote from.

**Balance tooling is spread out.**
About 20 scripts overlap: two batch runners, several report and table makers, and separate tools for Hard, thinking bots and member value. They work, but every balance thread rebuilds its own pipeline. I'd make one command that runs Normal, Hard and Very Hard on a chosen deck and writes one report. It would flag each card, color and space that's out of line at every level, and say how sure it is. That's the "really see what's out of place" read you asked for.

**Old branches.**
73 old thread branches sit on GitHub. None are needed, but deleting them can't be undone, so they stay until you say so.

**Where the rules don't reach.**
Chat threads still run none of the automatic checks. They depend on each thread running two commands by hand, and the voice check is the only thing between a thread and you. The new verdict line and the board fix help because they show up on their own when a thread starts.
