# How we operate: review (Nov 1, 2026)

The first version of this was about tests and scripts. That was the wrong read of "harness". This one covers how we work: threads, the coordinator, how decisions travel, the rules, and how we talk to you. The test fixes from last night are at the bottom, short.

## What's not working

**1. Your words get lost when they're handed on.**
Your message said "give our harness/way of working a once-over". The coordinator passed it on as "the ship script, test gates, balance tooling", and I built exactly that. It's the same kind of miss as "laggy" meaning freezing and not click speed (Oct 28), and the turn-rule mix-ups (Oct 22). Six of your 45 logged corrections are this kind. The cause is the same each time: a thread works from a summary of your words, not from your words.
*Fixed today:* threads check their goal against your own message, and anything the coordinator adds is only a suggestion. "Harness" is now defined in the rules as how we operate.

**2. Rules don't reach the threads where you work.**
Chat threads run none of the automatic checks. Every rule depends on each thread remembering to run two commands by hand. The tool that logs your corrections had silently dropped this morning's one too. Every thread also reads about 6,000 words of rules. Your project instructions and the repo rules repeat each other and disagree in places: your instructions say five lines at most, the repo rules say eight.
*Fixed today:* corrections always get logged now.
*Still open:* the rules need one home (decision 1).

**3. Nobody owns the shared picture.**
About ten threads pushed to the same game code in the last 36 hours, and we shipped about 140 releases in four days. Each thread updates the shared docs "when it can". The result: the hand-off docs a new thread reads first still say Oct 28 and Oct 29, about 100 versions behind live. Open questions for you are spread over at least three files (Oct 24, Oct 28, and threads' own messages). The status board showed only one thread for days, because every thread was overwriting the same line (fixed last night).

**4. Thread states cry wolf.**
Threads show as needing you when they don't. On Oct 31 you asked "why is this flagged as needing my attention" when nothing was. Right now **Balance the game for 0.99** shows as blocked on you. If the flag is often wrong, you stop trusting it.

**5. Big overnight asks have no plan you can see.**
"0.99 by morning" fanned out into several threads. Nobody posted one plan saying who does what, what's done by when, and which decisions are queued for your morning. So the morning arrives as a pile of separate thread updates.

**6. The weekly review lives in a closed thread.**
The Monday review of how we work was set up in the "Self-improving setup" thread, which is marked done. Whether it still fires is unclear, and that's exactly the kind of check that should catch the problems above.

## What changes (process is ours to run; the coordinator is putting B to D in place now)

**A. One home for the rules.** Your project instructions shrink to a short pointer. The repo rules stay the single source, cut to the rules that are still current. One copy can't disagree with itself.

**B. The coordinator owns the shared picture.** It is the only writer of the hand-off docs and of one "waiting on you" list. It brings you decisions three at a time and keeps thread flags honest. Threads report to it and write only their own status line.

**C. Fewer threads at once.** At most four threads change the game at the same time. Each big ask (like 0.99) starts with a one-screen plan from the coordinator, and you get one morning summary at a set time instead of a stream of thread messages.

**D. The weekly review moves to the coordinator** and runs on Monday mornings. It reads the week's corrections, finds any that came twice, and turns each into a rule or check that week.
